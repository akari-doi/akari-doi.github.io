HTMLの構造と意味（Semantics）

ハンバーガーメニューの実装（button🆗　div🆖）

<button type="button" class="sp-menu" aria-label="メニュー" aria-controls="header-nav" aria-expanded="false">
  <span></span>
  <span></span>
  <span></span>
</button>
<nav class="header-nav" id="header-nav" aria-hidden="true">
  ...
</nav>

ハンバーガーメニューの実装に div や a ではなく button を使用しています。

  • なぜ button なのか: このパーツは「別のページへの移動」ではなく、「メニューを開閉する機能」を持つスイッチだからです。button 要素を使うことで、キーボード操作（Tabキーでの選択やEnterキーでの実行）が自動的に可能になります。
  • aria-label="メニュー": ボタンの中身が「三本線」などの図形のみの場合、音声読み上げソフトには内容が伝わりません。aria-label を使って、これが「メニューボタンである」と明示します。

※補足（WAI-ARIAについて）:
今回は aria-controls（どの要素を操作するか）、aria-expanded（開いているか）、aria-hidden（隠されているか）という属性も記述しています。
これらは「スクリーンリーダー」などの支援技術に対して、メニューの開閉状態を正確に伝えるためのものです。JavaScriptで状態に合わせて値を書き換えますが、現段階では「アクセシビリティのための記述」という認識で十分です。

画像の出し分け（<picture>要素）

<picture class="mv">
  <source media="(min-width: 768px)" srcset="images/mv-pc.jpg">
  <img src="images/mv-sp.jpg" alt="...">
</picture>

CSS（display: none）で画像を隠すのではなく、HTMLの picture 要素を使ってブラウザに適切な画像を選ばせています。

  • アートディレクション: 単なる縮小ではなく、スマホ用には「被写体をより大きくトリミングした縦長の画像」、PC用には「横長の広角画像」といったように、画面サイズに合わせて最適な構図の画像を出し分けることができます。
  • パフォーマンス: スマホで閲覧しているユーザーには、PC用の巨大な画像データをダウンロードさせずに済みます。

alt 属性の書き分け

alt は「画像の説明」というより、画像が見えないときに、代わりに置かれる文章です。スクリーンリーダーはこの文章を読み上げ、画像が読み込めなかったときはこの文章が表示されます。

「この画像を文章に置き換えるなら何と書くか」で考えると、画像の役割によって書き方が変わります。今回のサイトでは3つのパターンがあります。

1. ロゴ：書かれている文字そのもの

<img src="images/logo.svg" alt="HAL BAKERY & CAFE">

ロゴは「文字を画像にしたもの」なので、書かれている文字をそのまま入れます。「ロゴ」「ロゴ画像」とは書きません。ヘッダーでは h1 の中にあるので、この alt がページの見出しの文章になります。

2. メインビジュアル：写真の内容

<img src="images/mv-sp.jpg" alt="HAL BAKERY & CAFEの店内の様子">

お店の雰囲気を伝える写真なので、何が写っているかを短く書きます。

3. 商品画像：空にする（考え方が2つあります）

<h3 class="pick-up-item-title">ハニーレモンスコーン</h3>
...
<img src="images/item-01.jpg" alt="">

今回は alt="" と空にしています。すぐ近くに商品名の見出し（h3）があるので、alt にも商品名を入れると、読み上げでは商品名が2回読まれてしまうからです。

  • alt を空にする: 近くの文章で同じ情報が伝わっているなら、重複させないという考え方です。空にすると、スクリーンリーダーはその画像を読み飛ばします。
  • 商品名を入れる: 画像が何であるかを必ず伝える、という考え方です。

どちらか一方だけが正解というわけではありません。「この alt がなくなったら、伝わらなくなる情報はあるか？」を基準に判断します。

注意：空にする場合も alt 属性そのものは消しません。alt="" は「この画像は読み飛ばしてよい」という意思表示ですが、alt 属性を書かないと、スクリーンリーダーがファイル名（item-01.jpg）を読み上げてしまうことがあります。

セクションと見出し（<section>のルール）

<section class="section">
  <h2 class="section-title">...</h2>

HTML Standardにおいて、section 要素は文書の「章」や「節」を表します。仕様上、セクションには通常、その内容を表す見出し（h1〜h6）が存在するべきとされています。

単に「ここを囲って背景色をつけたい」というデザイン上の理由だけで、見出しのない範囲に section を使うことは推奨されません。その場合は意味を持たない div を使用します。

カード型レイアウトのマークアップ（li？ div？）

今回のデザインでは、Pick UpとNews、どちらも一般的にリスト形式がよく使われるデザインになっています。今回はそれぞれ明確にタグを使い分けています。

  • News（お知らせ）: ul > li を使用
    お知らせは情報の並列な羅列であり、順序や一覧性に意味があるため、リスト構造が適しています。
  • Pick Up（商品紹介）: div を使用
    商品一つひとつに見出し（h3）が含まれています。
    HTML Standardでは、li要素の中に見出し要素を入れることは文法的には適合しているものの、意図したセマンティクスを伝えられない可能性があると指摘されています。見出しは新しいセクションを開始するため、リスト内に見出しがあるとリストが暗黙的に複数のセクションに分割されてしまいます。
    今回のPick Upセクションでは、各商品カードが見出しを持つ独立したコンテンツであるため、リスト構造ではなくdivでグルーピングする手法を採用しました。

フッターのナビゲーション

フッターにあるリンク集には nav 要素を使っていません。

nav 要素は「主要なナビゲーション」を表すために使われます。ページ内に複数の nav があると、スクリーンリーダーの利用者が「メインのメニュー」にたどり着くのを妨げる可能性があります。

もしフッターにも使う場合は <nav aria-labelledby="footer-nav-title"> のように、見出しのIDを参照して区別する方法が推奨されます（aria-label属性で直接ラベルを指定することも可能です）。今回はシンプルなリンク集のため div（または ul）で十分です。

<small> の本来の意味

<small>© 2025 HAL BAKERY & CAFE</small>

HTML5以降、small は「文字を小さくする装飾タグ」ではありません。「免責事項、警告、法的制約、著作権表示」などの注釈を表すタグとして定義されています。

見た目の文字サイズはCSSで制御しますが、コピーライト表記は意味的に small が最も適切です。

Googleマップの埋め込み（iframe）と title 属性

<iframe
  title="HAL BAKERY & CAFEの地図"
  src="https://www.google.com/maps/embed?..."
  width="600" height="450" loading="lazy" ...></iframe>

iframe は、ページの中に別のページを埋め込む要素です。Googleマップの「共有」→「地図を埋め込む」でコピーしたコードを貼り付けています。

title 属性は自分で足す

Googleからコピーしたコードには title 属性がついていません。そのままだと、スクリーンリーダーの利用者には「何かが埋め込まれている」ことしか伝わりません。そこで今回は、コピーしたコードに title 属性を自分で書き足しています。

title には「何が埋め込まれているか」を短く書きます。画像でいう alt のような役割です。YouTubeなど、ほかの埋め込みでも同じように足します。

そのほかの属性

  • width / height: Googleが用意した初期サイズです。今回はCSSで width: 100% と高さを指定して上書きしています。
  • loading="lazy": 画面に近づくまで読み込みを遅らせて、ページの表示を速くします。

ページ内リンク（アンカーリンク）

今回のサイトでは、ヘッダーとフッターのメニューから各セクションへジャンプできるように、ページ内リンク（アンカーリンク）を実装しています。

実装に必要な2つの作業

ページ内リンクを機能させるためには、リンク元とリンク先の両方を設定する必要があります。

1. リンク元：メニューの href 属性

ヘッダーとフッターのメニューに、ジャンプ先のIDを指定します。#（ハッシュ）の後にID名を記述します。

<!-- ヘッダーのナビゲーション -->
<nav class="header-nav">
  <ul class="header-nav-list">
    <li><a href="#pick-up">Pick Up</a></li>
    <li><a href="#information">Information</a></li>
    <li><a href="#news">News</a></li>
  </ul>
</nav>

<!-- フッターのナビゲーション -->
<ul class="footer-menu">
  <li><a href="#pick-up">Pick Up</a></li>
  <li><a href="#information">Information</a></li>
  <li><a href="#news">News</a></li>
</ul>

2. リンク先：各セクションの id 属性

ジャンプ先となる各セクションに、id属性を設定します。このid名は、リンク元の#以降の文字列と一致させる必要があります。

<section class="section section-pick-up" id="pick-up">
  <div class="section-inner">
    <h2 class="section-title">Pick Up</h2>
    ...
  </div>
</section>

<section class="section section-information" id="information">
  <div class="section-inner">
    <h2 class="section-title">Information</h2>
    ...
  </div>
</section>

<section class="section section-news" id="news">
  <div class="section-inner">
    <h2 class="section-title">News</h2>
    ...
  </div>
</section>

ページ内リンクの動作

この設定により、以下のような動作が実現できます：

  • <a href="#pick-up">をクリック → id="pick-up"のセクションへスクロール
  • <a href="#information">をクリック → id="information"のセクションへスクロール
  • <a href="#news">をクリック → id="news"のセクションへスクロール

重要なポイント

  • id属性の値は一意である必要があります - 同じページ内で同じid名を複数使用することはできません
  • id名は大文字小文字を区別します - #Pick-Upと#pick-upは別物です
  • href属性には必ず # を付けます - href="pick-up"ではなくhref="#pick-up"
  • id名は英数字とハイフン、アンダースコアが使えます - 数字から始めることはできません

CSSのネスト（CSS Nesting）

.card {
  background-color: #fff;

  /* ネスト（入れ子）の書き方 */
  .card-title {
    font-weight: bold;
  }

  /* &（アンパサンド）が必要な場合 */
  &:hover {
    opacity: 0.8;
  }
}

これまでSassなどのプリプロセッサが必要だった「入れ子構造（ネスト）」の記述が、CSS標準で使えるようになりました。

ポイント:

  • 単純な子孫セレクタ（例：.card .card-title）の場合、& を省略してそのまま入れ子にできます（リラックス構文）。
  • :hover などの疑似クラスや、クラスをつなげて記述する場合（例：.card.active）は、Sassと同様に &（親セレクタ自身）を使って記述します。

※注意：SassのBEM記法でよく使われる「文字列結合」（例：&__element と書いて .block__element を生成する機能）は、標準CSSのネストでは使用できません。

overflow-x: clip; と sticky の関係

横スクロールバーを消すために overflow-x: hidden; を body などに設定すると、子要素の position: sticky;（スクロール追従）が効かなくなるという仕様上の問題がありました。

overflow-x: clip; は、要素を「スクロールコンテナ」に変化させずに、はみ出した部分を単に切り取ります。これにより、sticky の機能を維持したまま、不要なスクロールバーを削除することができます。

position: sticky によるヘッダー固定

今回のプロジェクトでは、ヘッダーをposition: stickyで固定しています。スクロールしても画面上部に表示され続けます。

.header {
  position: sticky;
  top: 0;
  z-index: 2;
}

sticky の動作

  • 通常はposition: relativeのように配置される
  • スクロールして指定位置（top: 0）に達すると、その位置に固定される
  • position: fixedと違い、親要素の範囲内でのみ有効

z-index の役割

z-index: 2は、重なり順（奥行き）を制御します。数値が大きいほど手前に表示されます。ヘッダーが他のコンテンツの上に表示されるように設定しています。

今回の重なり順:

  • ヘッダー: z-index: 2
  • ナビゲーション: z-index: 10
  • その他のコンテンツ: デフォルト（z-index: auto）

nth-child による要素の選択

:nth-child() は、親要素の中で何番目の子要素かを指定してスタイルを適用できる擬似クラスです。

基本的な使い方

/* 3番目の要素 */
li:nth-child(3) { ... }

/* 偶数番目の要素 */
li:nth-child(even) { ... }

/* 奇数番目の要素 */
li:nth-child(odd) { ... }

/* 3の倍数番目の要素（3, 6, 9...） */
li:nth-child(3n) { ... }

重要："of S" 構文（最もわかりやすい方法）

従来の:nth-child()は「すべての子要素」の中から数えるため、途中に異なる要素が混ざっていると意図しない結果になることがありました。

"of S" 構文を使うと、「特定のセレクタに一致する要素だけ」を数えることができ、より直感的に書けます。

/* 従来の方法：すべての子要素の中から2番目の li */
li:nth-child(2) { ... }

/* "of S" 構文：li要素だけを数えて2番目 */
:nth-child(2 of li) { ... }

/* クラス名で絞り込み：.item クラスを持つ要素だけを数えて3番目 */
:nth-child(3 of .item) { ... }

/* 偶数番目の.card要素 */
:nth-child(even of .card) { ... }

実例での違い

<div>
  <h2>見出し</h2>
  <p class="item">アイテム1</p>
  <p class="item">アイテム2</p>
  <p class="item">アイテム3</p>
</div>
/* ❌ 従来の方法：「すべての子要素の2番目」= h2 が選択されてしまう */
.item:nth-child(2) { color: red; }

/* ✅ "of S" 構文：「.itemの中で2番目」= 正しくアイテム2が選択される */
:nth-child(2 of .item) { color: red; }

"of S" 構文を使うことで、HTMLの構造に左右されず、意図した要素を確実に選択できます。これが現在最もわかりやすい方法です。

今回のハンバーガーメニューでの応用例

今回のハンバーガーメニューの3本線も、"of S" 構文を使うことでより明示的に書けます。

/* 従来の書き方 */
span:nth-child(1) { top: 8px; }
span:nth-child(2) { 
  top: 50%; 
  transform: translateY(-50%); 
}
span:nth-child(3) { bottom: 8px; }

/* "of S" 構文を使った書き方（より明示的） */
:nth-child(1 of span) { top: 8px; }
:nth-child(2 of span) { 
  top: 50%; 
  transform: translateY(-50%); 
}
:nth-child(3 of span) { bottom: 8px; }

今回のケースでは button の直下に span しかないため結果は同じですが、"of S" 構文を使うことで「spanだけを数える」という意図が明確になり、より保守性の高いコードになります。

transform による中央配置（ハンバーガーメニューの実装）

ハンバーガーメニューの3本線を実装する際、真ん中の線を正確に垂直中央に配置する方法として、transform: translateY(-50%) を使用しています。

/* 1本目の線 */
span:nth-child(1) {
  top: 8px;       /* 上から8pxの位置 */
}

/* 2本目の線（真ん中） */
span:nth-child(2) {
  top: 50%;       /* 上から50%の位置（中央） */
  transform: translateY(-50%); /* 線の太さの半分だけ上にずらして、完全に垂直中央に */
}

/* 3本目の線 */
span:nth-child(3) {
  bottom: 8px;    /* 下から8pxの位置 */
}

なぜ transform: translateY(-50%) が必要なのか？

top: 50% だけを指定すると、要素の**上端**が親要素の中央に配置されます。しかし、これでは要素自体は中央より下にずれてしまいます。

▼ top: 50% だけの場合（ずれている）
要素が下にずれている
▼ top: 50% + translateY(-50%) の場合（正確に中央）
✓ 完全に中央

transform: translateY(-50%) は、要素自身の高さの50%分だけ上方向（Y軸のマイナス方向）に移動させます。これにより、要素の中心が親要素の中央に正確に配置されます。

  • top: 50%: 要素の上端を親の中央に配置
  • translateY(-50%): 要素を自身の高さの半分だけ上に移動
  • 結果: 要素の中心が親の中央に配置される

この手法は、高さが可変の要素でも確実に中央配置できるため、非常に実用的です。水平方向も同様に left: 50%; transform: translateX(-50%); で中央配置できます。両方を組み合わせて transform: translate(-50%, -50%); とすれば、上下左右完全に中央配置できます。

100vh ではなく 100dvh を使う理由

.header-nav {
  position: fixed;
  top: 0;
  height: 100dvh; /* 100vh ではなく 100dvh */
}

スマホのスライドメニューを画面の高さいっぱいにするために、100vh ではなく 100dvh を使っています。

vh は「画面（ビューポート）の高さの1%」という単位です。ところがスマホのブラウザでは、スクロールに合わせてアドレスバーが出たり引っ込んだりします。100vh は「アドレスバーが引っ込んだときの、いちばん広い高さ」で計算されるため、アドレスバーが出ている間は、要素の下のほうが画面の外にはみ出してしまいます。

  • 100vh: アドレスバーを考慮しない高さ（スマホでは実際の表示より大きくなることがある）
  • 100dvh: いま実際に見えている高さ。アドレスバーの出入りに合わせて変わります（d は dynamic の d）

今回のメニューは項目が上に3つあるだけなので 100vh でも見た目は困りませんが、メニューのいちばん下にボタンなどを置くデザインだと、100vh では押せなくなることがあります。

補足：ほかに svh（アドレスバーが出ているときの、いちばん狭い高さ）と lvh（引っ込んだときの、いちばん広い高さ）もあります。PCではどれも同じ値になります。

フォントサイズの計算（calc）

font-size: calc(26 / 16 * 1rem);

デザインカンプが「26px」で作られている場合、それをレスポンシブ対応しやすい rem 単位に変換する必要があります。

電卓で計算して 1.625rem と直接書く代わりに、CSSに calc(デザイン値 / ルート文字サイズ * 1rem) という計算式を書くことで、「元が何pxのデザインだったか」がコード上で明確になり、修正も容易になります。

補足：html { font-size: 62.5%; } を使う方法について

一部のサイトでは、htmlに対してfont-size: 62.5%;（10px相当）を設定し、フォントサイズを28pxなら2.8remとするやり方が見られます。この方法には以下のようなデメリットがあります：

  • アクセシビリティの問題： ブラウザのデフォルトフォントサイズ（通常16px）をユーザーが変更している場合、その設定を上書きしてしまいます。
  • サードパーティライブラリとの不整合： 外部CSSライブラリが16pxベースを前提にしている場合、デザインが崩れる可能性があります。

今回のようにhtmlのフォントサイズはデフォルト（16px）のままにしておき、各要素でcalc()を使って変換する方が、アクセシビリティとメンテナンス性の観点から望ましい方法です。

グリッドレイアウトの自動調整（auto-fit と minmax）

grid-template-columns: repeat(auto-fit, minmax(min(100%, 228px), 1fr));

※このボックスの幅が変化しています

  • min(A, B): AとBを比較して、小さい方の値を返すCSS関数です。今回のmin(100%, 228px)は、100%（親要素の幅）と228pxを比べて小さい方になります。通常は228pxが最小値になりますが、現在のSPデバイスではありえないものの極小画面では100%に収まる（はみ出し防止）仕組みです。今回228pxにしたのは、タブレット768pxのときに3カラムにしたかったからです。

box-shadow による影の表現

今回のプロジェクトでは、カードやナビゲーションに影を付けて立体感を出しています。box-shadowで影を作る際に、RGBのスラッシュ記法を使って透明度を指定しています。

.pick-up-item {
  box-shadow: 2px 2px 4px rgb(76 49 13 / 10%);
}

.header-nav {
  box-shadow: 2px 0 4px rgb(76 49 13 / 10%);
}

box-shadow の構文

box-shadow: x軸 y軸 ぼかし 色;

  • x軸: 横方向の影の位置（正の値で右へ）
  • y軸: 縦方向の影の位置（正の値で下へ）
  • ぼかし: 影のぼかし具合（数値が大きいほどぼける）
  • 色: 影の色

RGB スラッシュ記法による透明度指定

rgb(76 49 13 / 10%) の意味:

  • 76 49 13: RGB値（今回は --main の色 #4C310D）
  • / 10%: 透明度10%（アルファ値）

この記法を使うことで、影を薄く柔らかく表現できます。影に透明度を持たせることで、背景が透けて見え、より自然な立体感を演出できます。

画面幅いっぱいに広げる計算（Full Width）

width: 100vw;
margin: 0 calc(50% - 50vw);  /* 左右のネガティブマージン */
padding: 0 calc(50vw - 50%); /* 中身をコンテナ幅に戻す */

親要素（コンテナ）の幅制限を無視して、背景や画像などを画面の左端から右端まで（全幅）広げるための計算式です。

▼ 図解：コンテナの中から画面幅(100vw)まで突き抜けるイメージ
ブラウザ画面幅 (100vw)
100vwに広がる

仕組み:

  1. 親要素の中心（50%）を基準にします。
  2. そこから画面の半分（50vw）を引くことで、要素の左端を画面の左端に強制的に合わせます（ネガティブマージン）。
  3. これを左右（margin-leftとmargin-right）に適用することで、両側に広がります。
  4. 幅を 100vw に指定することで、画面いっぱいまで広がります。
  5. 補足（padding）: 背景だけを広げて、中のテキストなどは元のコンテナ幅（中央）に収めたい場合は、padding に逆の計算式 calc(50vw - 50%) を指定して内側に押し戻します。

Gridによる自由な配置（Newsセクション）

Newsセクションでは、display: grid を使い、grid-column（列）と grid-row（行）を指定しています。

これにより、HTMLの記述順（日付→タイトル→本文）を変更することなく、PC表示時だけ「1行目の左に日付、右にタイトル、2行目全体に本文」といった複雑なレイアウト変更を実現しています。

Grid の構造：トラック（Track）とライン（Line）

CSS Gridの配置を理解するには、トラックとラインの概念が重要です。

  • トラック（Track）： グリッドの行または列そのもの。上の図では、青い領域とオレンジの領域が「列トラック」、グレーの破線で囲まれた領域が「行トラック」です。
  • ライン（Line）： グリッドを区切る線。番号で指定します。赤い縦線が列ライン（1, 2, 3）、青い横線が行ライン（1, 2, 3）です。最後のラインは -1 でも指定できます。

実際の使用例（Newsセクション）

/* 日付 */
.news-item-date {
  grid-row: 1;      /* 行ライン1から2の間（1行目） */
  grid-column: 1;   /* 列ライン1から2の間（1列目） */
}

/* タイトル */
.news-item-title {
  grid-row: 1;      /* 行ライン1から2の間（1行目） */
  grid-column: 2;   /* 列ライン2から3の間（2列目） */
}

/* 本文 */
.news-item-text {
  grid-row: 2;      /* 行ライン2から3の間（2行目） */
  grid-column: 1 / -1; /* 列ライン1から最後まで（全列） */
}

grid-column: 1 / -1 の -1 は「最後のライン」を意味します。つまり「1列目から最後の列まで」という指定になります。

レスポンシブ対応でのスタイルの打ち消し

レスポンシブデザインでは、「PC用のスタイルをSP表示で打ち消したい（元に戻したい）」といった場面がよくあります。その際、CSSの適用順序を理解しておくことが重要です。

CSSの適用順序

CSSは以下の順序で適用されます（後のものほど優先度が高い）:

  1. 初期値（Initial Value）: CSS仕様で定義されている各プロパティの初期値
  2. ユーザーエージェントスタイルシート: ブラウザが提供するデフォルトスタイル（例: divはdisplay: block、h1の文字サイズ、ulの左余白など）
  3. サイト制作者が記述したCSS: 私たちが書くスタイル

スタイルを打ち消す方法

設定したスタイルを打ち消すには、主に2つの方法があります:

1. ユーザーエージェントスタイルシートの値を明示的に指定する

/* PCで設定したスタイル */
div {
  display: flex;
}

/* SPで打ち消す場合 */
@media (width < 769px) {
  div {
    display: block; /* divのユーザーエージェントスタイルシート値 */
  }
}

この例では、displayプロパティの初期値はinlineですが、div要素はユーザーエージェントスタイルシートでblockに設定されています。そのため、元に戻すにはdisplay: blockと明示的に指定します。

2. revertを使用する

/* PCで設定したスタイル */
div {
  display: flex;
}

/* SPで打ち消す場合: revertを使うとユーザーエージェントスタイルシートまで巻き戻る */
@media (width < 769px) {
  div {
    display: revert; /* 結果: block（divのユーザーエージェントスタイルシート値）になる */
  }
}

revertは、そのプロパティを「サイト制作者が記述したCSS」より前の段階（ユーザーエージェントスタイルシート）まで巻き戻します。ただし、ユーザーエージェントスタイルシートに定義がない場合は初期値まで戻ります。

重要: 各プロパティの初期値とユーザーエージェントスタイルシートの値を把握しておくことで、適切にスタイルを打ち消すことができます。例えば、displayの初期値はinlineですが、divはユーザーエージェントスタイルシートでblockになっています。

@media (width >= 769px) { ... }

従来の @media (min-width: 769px) という書き方の新しい構文です。

「幅が769px 以上（>=）」という条件が、数学の不等号を使って直感的に書けるようになりました。逆に「以下」の場合は <= を使用します。

プロパティを書く順序

実際の制作現場では、プロパティを一定のルールに従った順序で記述することが推奨されます。

WordPress CSSコーディング規約の順序

私はWordPress CSSコーディング規約に沿ってプロパティを記述しています：

  1. 画面（Display & Visibility）
    display, visibility, opacity など
  2. 位置（Positioning）
    position, top, right, bottom, left, z-index など
  3. ボックスモデル（Box Model）
    width, height, margin, padding, border など
  4. 色とフォント（Colors & Typography）
    color, font-family, font-size, line-height, background など
  5. その他（Other）
    transform, transition, animation など

記述例

.header {
  /* 画面 */
  display: flex;
  
  /* 位置 */
  position: sticky;
  top: 0;
  z-index: 100;
  
  /* ボックスモデル */
  width: 100%;
  padding: 10px 20px;
  
  /* 色とフォント */
  background-color: var(--bg);
  
  /* その他 */
  transition: box-shadow 0.3s;
}

他の方法

  • アルファベット順に並べる
  • CSS Combなどのツールで自動整形する
  • StylelintなどのLinterで統一ルールを適用する
  • Prettierで自動フォーマットする

VSCode拡張機能

  • 後から見ても理解しやすいコードにすること

JavaScriptとの連携

<script> の読み込み位置と defer 属性

<script src="js/main.js" defer></script>

従来は </body> の直前に書くことが多かったスクリプトですが、現在は <head> 内に defer 属性をつけて記述するのが主流です。

メリット: HTMLの解析（パース）を止めずにJavaScriptファイルを裏側で読み込み、HTMLの解析が終わった直後に実行されます。これにより、ページの表示速度（体感速度）が向上します。

defer の動作

  • スクリプトファイルの読み込みをバックグラウンドで実行
  • HTMLの解析を妨げない
  • HTMLの解析完了後、DOMContentLoadedイベントの前に実行
  • 複数のdeferスクリプトは記述順に実行される

今回のプロジェクトでは: JavaScriptがDOM（HTML要素）を操作するため、HTMLが完全に読み込まれた後に実行される必要があります。deferを使うことで、この順序が保証されます。

クラスの追加/削除による状態管理

今回のプロジェクトでは、JavaScriptでクラスを追加・削除することで、CSSのスタイルを動的に切り替えています。これは現代的なWeb開発の基本パターンです。

ハンバーガーメニューの開閉

// JavaScriptでクラスをトグル（追加/削除を切り替え）
menuButton.addEventListener('click', () => {
  menuButton.classList.toggle('active');
  headerNav.classList.toggle('active');
});
/* CSS側：activeクラスがある時のスタイル */
.header-nav {
  transform: translateX(-120%); /* 初期状態：画面外 */
  transition: transform 0.3s ease-in-out;
}

.header-nav.active {
  transform: translateX(0); /* active時：画面内 */
}

スクロール時のヘッダー影追加

// スクロール位置に応じてクラスを追加/削除
function updateHeaderShadow() {
  if (window.scrollY > 0) {
    header.classList.add('scrolled');
  } else {
    header.classList.remove('scrolled');
  }
}

window.addEventListener('scroll', updateHeaderShadow);
/* CSS側：scrolledクラスがある時のスタイル */
.header.scrolled {
  box-shadow: 0 2px 8px rgb(76 49 13 / 10%);
}

このパターンの利点

  • 関心の分離: JavaScriptは「状態管理」、CSSは「見た目」に専念できる
  • 保守性: スタイルの変更はCSSだけで完結、ロジックの変更はJSだけで完結
  • 再利用性: 同じクラス名を使えば、他の要素でも同じ動作を実現できる
  • デバッグしやすい: 開発者ツールでクラスの有無を確認できる

classList の主なメソッド

  • .add('className'): クラスを追加
  • .remove('className'): クラスを削除
  • .toggle('className'): クラスがあれば削除、なければ追加
  • .contains('className'): クラスがあるか確認（true/false を返す）
